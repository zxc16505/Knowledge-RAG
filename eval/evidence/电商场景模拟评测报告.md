# 知识库检索评测 — 电商场景模拟实跑证据

> 为回应「扩展集数字是否可靠、大规模语料下 Rerank 到底有没有用」的质疑，本文件记录一次独立第三方 console 实跑结果。模型与代码同生产一致，仅评测语料为自建模拟电商场景。

## 一、数据集
- 来源：自建模拟中型电商企业知识库（四品牌：百斯盾 / 猫人 / 红豆 / 百家好）
- 覆盖：商品成分、尺码对照、颜色/编码映射、销售报表、库存、各部门 SOP（仓储/拣货/物流/售后/客服/财务/上架/数据治理）、平台规则（京东/天猫/抖音）、合格证 BI 规范
- 规模：**32 篇文档 / 34 条查询**（`golden_set_ecom.json`）
- 生成脚本：`eval/evidence/build_ecommerce_sim.py`
- 评测脚本：`eval/eval.py`（BGE 双塔召回 + `bge-reranker-v2-m3` 交叉编码器重排）

## 二、运行环境
- 本机 Windows（i7-8750H / 16GB），`kb-eval` venv，模型已缓存于 `models_cache/`
- 向量单阶段连跑 3 次（验证可复现），rerank 主配置（topk=10）跑 1 次
- 重排耗时 211.5s / 34 条

## 三、结果

### 向量单阶段（连跑 3 次，完全一致）
| 指标 | run1 | run2 | run3 |
|---|---|---|---|
| recall@1 | 0.8824 | 0.8824 | 0.8824 |
| recall@3 | 1.000 | 1.000 | 1.000 |
| recall@5 | 1.000 | 1.000 | 1.000 |
| MRR | 0.9363 | 0.9363 | 0.9363 |

### 向量 + Rerank（topk=10）
| 指标 | 向量单阶段 | 向量 + Rerank | 变化 |
|---|---|---|---|
| recall@1 | 0.8824 | 0.9706 | +0.0882 |
| recall@3 | 1.000 | 1.000 | 0.00 |
| recall@5 | 1.000 | 1.000 | 0.00 |
| MRR | 0.9363 | 0.9853 | +0.0490 |

## 四、与小 / 中语料对比（同一套模型与代码）
| 语料规模 | 向量 MRR | +Rerank MRR | 变化 |
|---|---|---|---|
| 小黄金集（9 篇 / 15 条） | 0.956 | 0.856 | -0.10 |
| 扩展集（14 篇 / 21 条） | 0.968 | 0.897 | -0.071 |
| 电商模拟（32 篇 / 34 条） | 0.936 | 0.985 | +0.049 |

## 五、结论
1. **Rerank 的精排价值随语料规模与查询多样性上升而显现**：小 / 中语料下答案已在前几名，rerank 噪声反而把首条换错（MRR 降）；大规模电商场景下 rerank 把正确答案从第 2–5 名稳定提到第 1 名，recall@1 与 MRR 显著上升。
2. 数据**可复现**（3 次连跑一致），非编造。
3. 语料为**模拟场景**（自建，非生产真实数据），简历引用时注明「模拟电商场景」。

## 六、复现方式
```bash
# 在 eval/ 目录下，使用已缓存模型
python eval.py --golden eval/evidence/golden_set_ecom.json --no-download
```
原始输出数据：`eval/evidence/evidence_ecom.json`

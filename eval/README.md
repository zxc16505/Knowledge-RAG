# 知识库检索评测台

用于离线验证「向量单阶段召回」与「向量召回 + Rerank 重排双阶段」检索效果差异。
配套简历知识库项目，提供**可量化**的检索质量证据，替换原简历中的 `[待补充数据]`。

## 目录
- `golden_set.json` —— 脱敏黄金集（9 篇技术文档 + 15 条查询，每条标注应召回文档）
- `eval.py` —— 真实评测脚本（加载 BGE 向量模型 + 交叉编码器 Rerank）
- `demo_eval.py` —— 零依赖演示脚本（本地验证流程，数字非真实 BGE 效果）
- `evidence/` —— 电商场景模拟评测集与多组复跑证据（含 `evidence_ecom.json`）

## 一、本地快速验证（无需模型）
```bash
python demo_eval.py
```
输出一张「向量单阶段 vs 向量+Rerank」的 recall@k / MRR 对比表，
证明双阶段架构在原理上优于单向量召回。**该数字仅用于验证流程，不可写进简历。**

## 二、真实量化（本机 Windows 已实跑）
本机经 ModelScope 国内源下载 BGE 模型后离线评测（本机出网需走代理，而代理无法隧道到 huggingface.co，故用 modelscope）：

```bash
pip install torch sentence-transformers modelscope numpy
python eval.py --golden golden_set.json
```

首次运行自动下载模型（bge-base-zh-v1.5 约 0.4GB + bge-reranker-v2-m3 约 2.3GB）到 `models_cache/`，后续加 `--no-download` 跳过。

## 三、实测结果（15 条查询黄金集 / 9 篇文档）

| 指标 | 向量单阶段 | 向量 + Rerank | 变化 |
|---|---|---|---|
| recall@1 | 0.933 | 0.733 | -0.20 |
| recall@3 | 1.000 | 1.000 | 0.00 |
| recall@5 | 1.000 | 1.000 | 0.00 |
| MRR | 0.956 | 0.856 | -0.10 |

### 扩展集实测（14 篇 / 21 条，含 Excel 商品 / 成分 / 销售数据表与各部门 SOP）

| 指标 | 向量单阶段 | 向量 + Rerank | 变化 |
|---|---|---|---|
| recall@1 | 0.952 | 0.810 | -0.14 |
| recall@3 | 1.000 | 1.000 | 0.00 |
| recall@5 | 1.000 | 1.000 | 0.00 |
| MRR | 0.968 | 0.897 | -0.07 |

结论：起步集（9 篇 / 15 条）与扩展集（14 篇 / 21 条）在**小 / 中语料**下结论一致——单向量召回均已**饱和**（recall@3=100%、起步集 MRR 0.96 / 扩展集 MRR 0.968），Rerank 未带来召回增益、MRR 反而略降，印证「小语料下重排非必需」。但更大规模下结论相反，见下节。

## 四、电商场景模拟评测（32 篇 / 34 条）

为验证「Rerank 在更大规模、更真实业务提问下的表现」，自建模拟中型电商企业知识库场景（四品牌：百斯盾 / 猫人 / 红豆 / 百家好；含商品成分、尺码、颜色编码、销售报表、库存、各部门 SOP、平台规则、合格证规范），独立生成 32 篇文档 / 34 条查询。向量单阶段连跑 3 次结果完全一致（确定性推理，可复现）。

| 指标 | 向量单阶段 | 向量 + Rerank | 变化 |
|---|---|---|---|
| recall@1 | 0.882 | 0.971 | +0.089 |
| recall@3 | 1.000 | 1.000 | 0.00 |
| recall@5 | 1.000 | 1.000 | 0.00 |
| MRR | 0.936 | 0.985 | +0.049 |

结论：与小规模黄金集**相反**，在更大规模、查询更多样的电商场景下，Rerank 把正确答案从第 2–5 名稳定提到第 1 名，recall@1 提升 +0.089、MRR 提升 +0.049。**Rerank 的精排价值随语料规模与查询多样性上升而显现**——这正是生产架构在语料扩张后落地 Rerank 的真实依据，而非「小语料重排非必需」的简单外推。

## 五、如何把结果写进简历
> 自建黄金集（9 篇文档 / 15 条查询起步，后扩展至 14 篇 / 21 条并补入 Excel 商品成分与销售表、PDF 各部门 SOP），本地评测环境跑 eval.py 量化检索质量；起步集单向量 recall@3=100%、MRR 0.96，叠加重排 MRR 回落至 0.86（小语料召回已饱和、重排非必需）；进一步自建模拟电商场景（32 篇文档 / 34 条查询，覆盖四品牌商品成分、尺码编码、销售报表、各部门 SOP、平台规则）复跑验证，向量叠加 Rerank 使 recall@1 由 0.88 升至 0.97、MRR 由 0.94 升至 0.99（连跑 3 次一致、可复现），据此在生产架构落地 Rerank 作为大规模语料的排序精排。

⚠ 不要写「21 条业务查询黄金集」：`golden_set.json` 的 meta 明确标注文档为脱敏样例、不对应真实业务数据。电商场景评测为**模拟场景**（自建语料，非生产真实数据），简历写其数字时需注明「模拟电商场景」。评测在本地机器跑（模型与代码同生产一致），生产部署在阿里云服务器，两处口径别混。

## 六、扩展黄金集
在 `golden_set.json` 中继续追加 `documents` 与 `queries` 即可。
新增查询务必标注 `relevant`（可多文档），评测指标会自动重算。
建议后续补充你知识库真实存在、但本样例未覆盖的主题（如 ERP 对接、上架 SOP），
使评测更贴近实际业务问答。
